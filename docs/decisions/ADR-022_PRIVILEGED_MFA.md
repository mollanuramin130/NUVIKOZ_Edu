# ADR-022 — Privileged MFA checkpoint

AUTH-06 uses RFC 6238 SHA-1, six digits, 30-second steps, ±one-step drift and strict last-counter replay prevention. The direct implementation has deterministic tests against all six published SHA-1 eight-digit RFC vectors. Per-user seed encryption uses Laravel authenticated encryption, not a source-controlled key. Enrollment remains pending for ten minutes; password reconfirmation is required at start, confirmation, challenge and recovery-code regeneration. Existing enrolled seeds cannot be replaced/reset through this API. Recovery codes are eight random 128-bit values, SHA-256 hashes at rest, single-use under the same user/credential locks. No SMS or external QR service.

Browser password login establishes limited school context and a five-minute challenge deadline, not administrative authority. Confirm/challenge rotates session ID/CSRF after DB commit. Assurance expires after 15 minutes, binds user/membership/role/identifier/credential, school, enrollment version and session ID, and cannot extend the 12-hour absolute session lifetime. Every School Admin protected browser command and SchoolAccess.requireAdmin service check requires current assurance. /me and MFA bootstrap alone remain available before verification. Teachers/family are not forced into privileged enrollment.

Activation/recovery proof redemption revalidates the issuer with requireAdminIdentity rather than demanding that the unrelated issuer remain signed in while the holder redeems a proof. Issuance/reissue still require the current issuer's MFA, tenant, role and ordinary lifecycle checks. Password recovery never deletes MFA enrollment; credential change invalidates old assurance. Production delivery remains disabled.

Legacy device provisioning and platform health are closed. A school token or platform-looking abilities string is not MFA assurance. There is no approved platform login issuer or native privileged-device challenge; no bypass issuer/reset/seed-replacement API is introduced. Platform sign-in, independently verified MFA reset and native privileged-device MFA are explicit dependencies, not completed portals. Unsupported actions fail closed.

Lock order: school → identity → membership → MFA credential/recovery code. Database mutations/audit commit before writing session assurance. Decryption/audit/validation failures do not downgrade security. Sensitive request fields password/secret/code are excluded from flashed input. No proofs/seeds/codes in account lists, storage, URLs or logs.
