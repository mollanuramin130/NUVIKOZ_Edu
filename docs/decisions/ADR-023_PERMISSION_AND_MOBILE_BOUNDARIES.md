# ADR-023 — Bounded delegation and mobile persistence boundary

Use a fixed backend capability registry with per-role ceilings, school-bound current authorization, version-conflict handling and transactional append-only audit. Synthetic capability probes test authorization before future academic/financial modules exist. No arbitrary frontend capability strings, fixed-power delegation or cross-school role union. Last-active-SA membership removal locks the school through the actual update; deletion is unsupported. Initial bootstrap is distinct. Global identity/bulk administration has no public route; future commands need all affected school locks and equivalent eligibility/audit/revocation checks. Raw privileged database administration is outside Eloquent guards.

Native tokens remain distinct from browser cookies. Add only server-derived context to the existing login DTO. Flutter transport refuses redirects/URL credentials, limits response size/time, and revalidates restored school/identity. The source-only scaffold has no installed OS secure-store handler. A fail-closed MethodChannel adapter is preferable to unverified persistent storage: default authentication stops before credentials are sent when the handler is absent. Only tests may use an in-memory fake. Android/iOS keychain/keystore implementation, native build and on-device validation remain explicit dependencies. Preserve checksum verification, kernel metadata denial and privilege dropping before any Flutter CI command.

Identity model security changes that remove eligibility (inactive status, platform flag, pending activation or forced setup) now lock all current active-SA schools in ID order before the identity and memberships, and apply the same last-admin guard before the actual update. Password-only rotation retains its existing identity lock. Independent MariaDB races cover identity deactivation versus deactivation and versus membership demotion. Initial bootstrap remains separate; no global administration API is added.
