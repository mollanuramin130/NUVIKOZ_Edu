# M2 implemented academic browser subset

Machine contract: `packages/contracts/m2-academic.openapi.json`. Approved generic `/sessions`, `/classes` and other target routes remain DESIGN_ONLY until individually implemented. Actual routes here: GET/POST `/api/v1/browser/academic/sessions` and `/api/v1/browser/academic/classes`. Browser-only; mobile token API unchanged. No device-token substitution.

Existing exact Origin, credentialed CORS, host-only Secure HttpOnly cookies, CSRF, no-store, current-session/tenant and School Admin MFA middleware remain in place. Services independently reload current identity/membership/school and require current MFA. Principal/Teacher/family/platform identities cannot use this setup subset; future scoped read journeys require their own policies. Writes lock school → user → membership; revalidate eligibility/MFA/entitlement after waiting. Expired entitlement permits authorized reads, not new commands/replay.

Session input follows SessionCreate: name (1–60), starts_on and ends_on ISO dates, end >= start, start strictly after today in configured valid IANA `schools.settings.timezone`. No implicit timezone; unavailable setup denies403. State is server-owned `future`, version1. Missing global session rule infrastructure means nullable rule_version, not a fabricated inherited version. Inclusive future/active date intersections and duplicate same-school names conflict409. No activation/close/edit/delete, active-boundary approval or global default workflow is claimed.

Class input follows ClassCreate: name (1–80), optional nullable grade_label (max32), sort_order0..2147483647. Names trim outer whitespace; no limit to Class8. Same-school duplicate name conflicts409 (database collation governs case equality). Class offerings are explicit Slice B commands; no teacher, student or guardian auto-creation.

Writes require Idempotency-Key matching `[A-Za-z0-9_-]{16,160}`. Scope: school + actor membership + operation + key. Canonical sorted validated JSON SHA256 binds body; changed body409. Exact retry returns the same resource and replayed=true, without another audit. Reauthorization precedes every replay. Receipt/resource/audit commit together; audit failure rolls everything back. Keys are not credentials. Strings versus numeric JSON types are distinct idempotency bodies.

GET returns `{data:{items:[],next_cursor:null},meta:{request_id:...}}`, at most25 rows ordered by immutable ULID; query accepts only an optional ULID cursor. Unknown fields422, unauthorized403, missing session401, CSRF419, conflicts409 and rate limit429. POST rate20/minute namespace academic-create. No server-trusted school/role/state/version from request.

Demo limits are bounded engineering defaults (10 sessions/50 classes per school), serialized within the same school lock; expired Demo denies writes. No user files/documents are created. Backend integration acceptance is separate from UI/mobile/owner acceptance.

## Slice B — implemented relationship subset

Four additional kinds expose GET/POST under `/api/v1/browser/academic/`: `class-offerings`, `sections`, `subjects`, `subject-offerings`. Same current School Admin + MFA/browser boundary and common response envelopes, CSRF, throttle, idempotency and audit as Slice A. No public device-token route added. All inputs follow allowlists and reject school/id/version/state injection.

- Class offering: `{session_id,class_id}`; both same-school, class unarchived, session state future and start date strictly after school-local today. Unique school+session+class. No automatic session activation or boundary edits.
- Section: `{class_offering_id,name,class_teacher_membership_id?:null}`, trimmed name1–40; unique school+offering+name. Teacher assignment infrastructure lacks staff profiles/effective-dated academic scope, so non-null teacher assignment is422, including a same-school membership. Nullable composite FK preserves the future boundary without issuing authority. No student counts, enrollment stubs or fake teachers.
- Subject: `{code,name}`, trimmed code1–32/name1–100; school-wide reusable definition, unique school+code. No curriculum/grading defaults. Database collation governs code/name case comparison.
- Subject offering: `{class_offering_id,subject_id,compulsory}`, actual JSON boolean required (false is optional, true is required); same-school offering and unarchived subject; unique school+offering+subject. No automatic assignment to every class.

Section and subject-offering session/class are derived exclusively through their class offering: no second independently writable session/class field exists. Those fields are rejected422 if injected. Class/subject masters can legitimately recur in distinct session offerings. Child creation and idempotent replay revalidate the current parent session eligibility and unarchived class/subject; closed/active/archived or stale future dates deny409. Future-session writes still require an already configured valid IANA school timezone. No new session transition workflow is introduced.

Lists remain25-item ULID cursor projections and accept additional optional same-school filters: class-offerings `session_id,class_id`; sections `class_offering_id`; subject-offerings `class_offering_id,subject_id`. Multiple filters AND together. Unknown query fields422; malformed ULID422; missing/foreign referenced resource404 with the same generic envelope. Reads retain historical relationship IDs across session states and expired entitlement, subject to current identity/school/MFA. Backend offers no direct history mutation/delete operation.

Demo totals per school:10 sessions,50 classes,100 class offerings,200 sections,100 subjects,500 subject offerings. These are bounded engineering defaults in `config/academic.php`, not a new commercial policy. Matching authorized retries do not consume another record; expired Demo/entitlement and revoked authority still block retries. Four new resource types reuse existing academic command receipts with distinct operations; domain row, receipt and append-only audit commit atomically. School→identity→membership locks serialize eligibility, duplicates and Demo quota checks. All future academic state/archive mutation services must acquire the same school lock; raw privileged SQL is not a supported application command.

Contract version0.2.0 is a supported subset. No standalone active-session setup, teacher assignment, academic UI, mobile domain workflow or owner acceptance is claimed.
